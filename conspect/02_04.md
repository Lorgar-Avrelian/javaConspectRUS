## 2.4 Java Collections Framework

> [[_оглавление_]](../README.md)

[**Коллекция (Collection)**](/conspect/definitions.md/#к) - это объект, который хранит в себе набор других однотипных
объектов, а также позволяет получить к ним доступ с помощью своих методов.

![16.png](/pictures/16.png)

Все коллекции наследуются от интерфейса **_Iterable_**, позволяющего проходить по всем значениям коллекций, которые
используют этот интерфейс (итерироваться).  
Интерфейс _Iterable_ наследует интерфейс _Collection_, который в свою очередь наследуют уже более узкие структуры:
списки (_List_), множества (_Set_) и очереди (_Queue_).

Особняком стоит интерфейс _Map_, который не наследуется от интерфейса _Iterable_, но также является составной частью
_Java Collection Framework_.

Отличия коллекций от массивов:

- коллекции могут хранить свои данные в массиве (_ArrayList_) или связывать объекты друг с другом, создавая определённый
  порядок (_LinkedList_), а могут и наоборот - не иметь порядка внутри и напоминать что-то вроде «кучи» или «мешанины»
  из объектов (_HashSet_);
- коллекции сами следят за количеством заполненных ячеек или связанных объектов и сами расширяются;
- коллекции имеют свои методы, которые можно использовать, переопределять и наследовать.

Так как коллекции являются полноценными объектами, в них переопределён метод `toString()`.  
Итерироваться по коллекциям можно с помощью [циклов](/conspect/01_03.md/#13-циклы).

За тип данных, которые находятся в коллекции, отвечает механизм
[дженериков](/conspect/02_02.md/#2231-дженерики-параметрический-полиморфизм).

_Java Collection Framework_ предоставляет разнообразный набор классов и интерфейсов для работы с ними, позволяя хранить,
извлекать, манипулировать и агрегировать данные.

_Java Collection Framework_ включает:

- Основные интерфейсы:
    - **_Collection_** - корневой интерфейс для всех коллекций, кроме карт (_maps_); определяет базовые операции
      (например, добавление, удаление, проверка размера):
        * **_List_** - определяет упорядоченную коллекцию, которая может содержать дублирующиеся элементы; элементы
          можно
          получать по индексу:
            + _ArrayList_ - реализация на основе динамического массива; предоставляет быстрый доступ к элементам по
              индексу;
            + _LinkedList_ - связный список, обеспечивающий быстрые вставку и удаление элементов;
            + _Vector_ - синхронизированный динамический массив (устаревший):
                - _Stack_ - расширение класса _Vector_, реализующее структуру данных стек (_LIFO_);
        * **_Set_** - коллекция, не содержащая дублирующихся элементов:
            + _HashSet_ - хэш-таблица, предоставляющая быстрые операции вставки, удаления и поиска;
            + _LinkedHashSet_ - хэш-таблица с сохранением порядка добавления элементов;
            + _TreeSet_ - отсортированное множество на основе красно-чёрного дерева;
        * **_Queue_** - коллекция для хранения элементов в порядке обработки; поддерживает операции вставки, извлечения
          и
          инспекции:
            + _LinkedList_ - может также использоваться как реализация _Queue_;
            + _PriorityQueue_ - очередь, организующая элементы согласно их приоритетам;
            + _Deque_ - двусторонняя очередь, позволяющая вставку и удаление элементов с обоих концов:
                - _ArrayDeque_ - реализация на основе динамического массива;
- Карты (_Maps_):
    - **_Map_** - объект, который хранит пары "ключ-значение"; ключи уникальны, а значения могут дублироваться:
        * _HashMap_ - хэш-таблица для хранения пар "ключ-значение"; не гарантирует порядок элементов;
        * _LinkedHashMap_ - хэш-таблица с сохранением порядка добавления элементов;
        * _TreeMap_ - отсортированная карта на основе красно-чёрного дерева;
        * _Hashtable_ - потокобезопасная реализация _Map_ (устаревшая, использование _ConcurrentHashMap_
          предпочтительнее);
- Специализированные коллекции:
    - **_EnumSet_** - высокоэффективная реализация интерфейса _Set_ для использования с перечислениями (_enums_);
    - **_EnumMap_** - реализация интерфейса _Map_, предназначенная для использования с ключами типа _enum_.

_Java Collection Framework_ обеспечивает мощные абстракции для работы с коллекциями данных, позволяя разработчикам
выбирать структуры данных, наиболее подходящие под конкретные задачи, учитывая их производительность и особенности
работы с данными.

### 2.4.1 Список (List)

> [[_оглавление_]](../README.md)

[**Список (List)**](/conspect/definitions.md/#l) - это последовательность элементов в определённом порядке.  
Его реализует интерфейс `List` пакета `java.util`.

Особенности списков:

- могут иметь повторяющиеся элементы;
- могут содержать элементы $\textrm{\color{orange}null}$;
- в списке могут быть элементы разных дочерних типов или элементы, реализующие один интерфейс;
- всегда сохраняют порядок вставки и предоставляют доступ к элементам по индексу;
- к элементам списка можно получить доступ, используя индексы, начиная с `0`.

Интерфейс `List` реализуют классы `ArrayList`, `LinkedList`, `Vector` и `Stack` (который расширяет класс `Vector`).

#### 2.4.1.1 Динамический массив (ArrayList)

> [[_оглавление_]](../README.md)

[**ArrayList**](/conspect/definitions.md/#a) - это динамический массив, представляющий собой упорядоченный набор данных, 
аналогичный массиву.

При создании объекта `ArrayList` создаётся массив. По умолчанию размер такого списка равен 10 и он заполнен
элементами $\textrm{\color{aqua}0}$, $\textrm{\color{aqua}0.0}$, $\textrm{\color{orange}false}$ или
$\textrm{\color{orange}null}$.  
Каждый раз, когда свободные ячейки заканчиваются, коллекция создаёт новый массив длиной в полтора раза больше
предыдущего.

На длину нового массива действует два фактора:

- количество минимально необходимых ячеек;
- фактор роста (обычно увеличение должно происходить не меньше чем в полтора раза).

Элементы из старого массива копируются в новый массив в том же порядке.

Данная реализация интерфейса `List` не синхронизирована и не годится для одновременного использования несколькими
потоками приложения. Для создания синхронизированной реализации интерфейса `List` на основе `ArrayList` необходимо
обернуть последний в момент инициализации, используя метод `synchronizedList()` класса `Collections`:

```java
public static void main(String[] args) {
    List<String> synchronizedList = Collections.synchronizedList(new ArrayList<>());
}
```

##### 2.4.1.1.1 add()

> [[_оглавление_]](../README.md)

Метод `add()` класса `ArrayList` применяется для добавления значений в список.  
Синтаксис метода выглядит следующим образом:

$\textrm{\color{white}list.add(\color{green}[значение]\color{white})}$  
$\textrm{\color{white}list.add(\color{aqua}[индекс ячейки]\color{white}, \color{green}[значение]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    List<String> list = new ArrayList<>();
    list.add("first");
    System.out.println(list);
    list.add(0, "null");
    System.out.println(list);
}
```

Вывод:

```text
[first]
[null, first]
```

Данный метод по умолчанию добавляет значение в конец списка, а при указании индекса - в ячейку с указанным индексом (при
этом все другие значения в списке сдвигаются на единицу).

##### 2.4.1.1.6 remove()

> [[_оглавление_]](../README.md)

Метод `remove()` класса `ArrayList` применяется для удаления из списка значения с указанным индексом (по умолчанию) или
равного указанному.  
Синтаксис метода выглядит следующим образом:

$\textrm{\color{orange}boolean \color{white}[имя переменной] = list.remove(\color{green}[значение]\color{white})}$  
$\textrm{\color{orange}[тип значения]
\color{white}[имя переменной] = list.remove(\color{aqua}[индекс ячейки]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    List<String> list = new ArrayList<>(List.of("first", "second", "third"));
    String remove = list.remove(0);
    System.out.println(list);
    boolean first = list.remove("first");
    System.out.println(first);
    System.out.println(remove);
    System.out.println(list);
}
```

Вывод:

```text
[second, third]
false
first
[second, third]
```

Данный метод удаляет из списка значение с указанным индексом или равное указанному (при этом все другие значения в
списке сдвигаются на единицу).  
В случае, если значение по указанному индексу в списке не найдено, будет выброшена ошибка _IndexOutOfBoundsException_.

##### 2.4.1.1.8 addAll()

> [[_оглавление_]](../README.md)

Метод `addAll()` класса `ArrayList` применяется для добавления всех значений из коллекции в текущий список.  
Синтаксис метода выглядит следующим образом:

$\textrm{\color{orange}boolean \color{white}[имя переменной] = list.addAll(\color{magenta}[добавляемая коллекция]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    List<String> list = new ArrayList<>(List.of("first", "second", "third"));
    List<String> list2 = new ArrayList<>(List.of("one", "two", "three"));
    list2.add(null);
    boolean b = list.addAll(list2);
    System.out.println(b);
    System.out.println(list);
}
```

Вывод:

```text
true
[first, second, third, one, two, three, null]
```

Данный метод добавляет в список все значения, содержащиеся и в порядке в копируемой коллекции. При этом в случае
успешного копирования метод возвращает $\textrm{\color{orange}true}$, иначе - $\textrm{\color{orange}false}$.

##### 2.4.1.1.10 isEmpty()

> [[_оглавление_]](../README.md)

Метод `isEmpty()` класса `ArrayList` применяется для определения наличия в списке не нулевых элементов.

```java
public static void main(String[] args) {
```

Данный метод возвращает $\textrm{\color{orange}true}$, если в списке содержится хотя бы один элемент, значение которого
не равно $\textrm{\color{orange}null}$, иначе - $\textrm{\color{orange}false}$.

##### 2.4.1.1.11 sort()

> [[_оглавление_]](../README.md)

Метод `sort()` класса `ArrayList` применяется для сортировки элементов списка по заданному правилу, передаваемому в
компараторе.  
Синтаксис метода выглядит следующим образом:

$\textrm{\color{white}list.sort()}$  
$\textrm{\color{white}list.sort(\color{purple}[компаратор]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    List<Integer> list = new ArrayList<>(List.of(2, 3, 1));

```

Вывод:

```text

[3, 2, 1]
```

Данный метод осуществляет сортировку элементов списка, не изменяя его размера.

##### 2.4.1.1.12 toArray()

Метод `toArray()` класса `ArrayList` применяется для преобразования списка в массив объектов.

$\textrm{\color{white}Object[] [имя переменной] = list.toArray()}$

##### 2.4.1.1.13 subList()

```text
	at lorgar.avrelian.Main.main(Main.java:16)
```

Данный метод возвращает список копий объектов того же типа, которые содержатся в исходном списке, начиная с первого 
указанного индекса включительно, заканчивая последним указанным индексом не включительно.  
В случае, если значение по указанному индексу в списке не найдено, будет выброшена ошибка _IndexOutOfBoundsException_.

#### 2.4.1.2 Двусвязный список (LinkedList)

> [[_оглавление_]](../README.md)

[**LinkedList**](/conspect/definitions.md/#l) - это двусвязный список (реализация интерфейсов `List` и `Deque`), 
реализующий все необязательные операции со списком и разрешающий использование всех элементов (включая 
$\textrm{\color{orange}null}$).

В основе _LinkedList_ лежит объект `Node`. Он имеет поля, которые соответствуют следующему элементу, предыдущему
элементу и значению.  
Сам объект `LinkedList` знает о существовании только первого и последнего элементов списка.

![17.png](/pictures/17.png)

В момент добавления элемента в `LinkedList` происходит следующее:

- создаёт объект `Node`;
- в него укладывается нужный элемент;
- объект `Node` встраивается в цепочку из объектов списка, заполняя поля `Node` внутри ссылками на прошлый элемент и
  следующий (двусвязный список).

Удаление элементов `Node` производится путём копирования ссылок двух соседних элементов друг на друга и обнулением этих
ссылок у текущего `Node`, в результате чего текущий элемент оказывается отрезанным от соседей и удаляется сборщиком
мусора при следующем прохождении. Операции, которые вносят индекс в список, проходят по списку с начала или с конца, в 
зависимости от того, что ближе к указанному индексу.

Поиск элемента в `LinkedList` производится последовательным перебором всех элементов.

#### 2.4.1.4 Стек (Stack)

> [[_оглавление_]](../README.md)

[**Stack**](/conspect/definitions.md/#s) - это стек объектов, реализующий принцип _LIFO_ и расширяющий класс `Vector`.

При инициализации стека создаётся пустой стек.

##### 2.4.1.4.1 push()

> [[_оглавление_]](../README.md)

Метод `push()` класса `Stack` применяется для помещения элемента на вершину стека (аналогичен методу `add()`, но в
отличие от него возвращает значение самого добавленного элемента, а не булев результат выполнения операции добавления):

$\textrm{\color{orange}[тип значений] \color{magenta}[имя переменной] 
\color{white}= stack.push(\color{green}[значение элемента]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    Stack<Integer> stack = new Stack<>();
    boolean add = stack.add(1);
    Integer push = stack.push(2);
    System.out.println(add);
    System.out.println(push);
    System.out.println(stack);
}
```

Вывод:

```text
true
2
[1, 2]
```

Данный метод возвращает значение добавленного элемента.

##### 2.4.1.4.2 pop()

> [[_оглавление_]](../README.md)

Метод `pop()` класса `Stack` применяется для получения и удаления верхнего элемента из стека:

$\textrm{\color{orange}[тип значений] \color{magenta}[имя переменной] \color{white}= stack.pop()}$

Пример:

```java
public static void main(String[] args) {
    Stack<Integer> stack = new Stack<>();
    stack.add(1);
    stack.push(2);
    stack.push(3);
    System.out.println(stack);
    Integer pop = stack.pop();
    System.out.println(pop);
    System.out.println(stack);
}
```

Вывод:

```text
[1, 2, 3]
3
[1, 2]
```

Данный метод выбрасывает исключение _EmptyStackException_, если стек пуст.

##### 2.4.1.4.3 peek()

> [[_оглавление_]](../README.md)

Метод `peek()` класса `Stack` применяется для получения верхнего элемента из стека без его удаления:

$\textrm{\color{orange}[тип значений] \color{magenta}[имя переменной] \color{white}= stack.peek()}$

Пример:

```java
public static void main(String[] args) {
    Stack<Integer> stack = new Stack<>();
    stack.add(1);
    stack.push(2);
    stack.push(3);
    System.out.println(stack);
    Integer peek = stack.peek();
    System.out.println(peek);
    System.out.println(stack);
}
```

Вывод:

```text
[1, 2, 3]
3
[1, 2, 3]
```

Данный метод выбрасывает исключение _EmptyStackException_, если стек пуст.

##### 2.4.1.4.4 empty()

> [[_оглавление_]](../README.md)

Метод `empty()` класса `Stack` проверяет, является ли стек пустым:

$\textrm{\color{orange}boolean \color{magenta}[имя переменной] \color{white}= stack.empty()}$

Пример:

```java
public static void main(String[] args) {
    Stack<Integer> stack = new Stack<>();
    stack.push(1);
    boolean empty = stack.empty();

    System.out.println(empty);
}
```

Вывод:

```text
[1]
false
[]
true
```

##### 2.4.1.4.5 search()

> [[_оглавление_]](../README.md)

Метод `search()` класса `Stack` возвращает расстояние от вершины стека до ближайшего к вершине стека вхождения 
(считается, что самый верхний элемент в стеке находится на расстоянии `1`):

$\textrm{\color{orange}int \color{magenta}[имя переменной] 
\color{white}= stack.search(\color{green}[значение элемента]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    Stack<Integer> stack = new Stack<>();
    stack.push(1);
    stack.push(2);
    stack.push(3);

    System.out.println(search);
    search = stack.search(4);
    System.out.println(search);
}
```

Вывод:

```text

-1
```

В случае, если искомого элемента нет в стеке, метод возвращает `-1`.

### 2.4.2 Множество (Set)

> [[_оглавление_]](../README.md)

[**Множество (Set)**](/conspect/definitions.md/#s) - это коллекция уникальных однотипных элементов, содержащая не более 
одного нулевого значения.

В некоторых реализациях `Set` есть ограничения на элементы, которые они могут содержать. Например, в некоторых 
реализациях запрещены элементы $\textrm{\color{orange}null}$, а в некоторых есть ограничения на типы их элементов.

Попытка добавить недопустимый элемент вызывает непроверяемое исключение, обычно _NullPointerException_ или 
_ClassCastException_.

Интерфейс `Set` имеет ряд стандартных реализаций:

- `HashSet` - основан на хеш-таблице, не сохраняет порядок элементов, допускает $\textrm{\color{orange}null}$;
- `LinkedHashSet` - расширяет `HashSet`, сохраняет порядок добавления элементов;
- `TreeSet` - реализует интерфейс `NavigableSet`, хранит элементы в отсортированном порядке в соответствии с реализацией 
  интерфейса `Comparable` в элементе или интерфейса `Comparator` в конструкторе;
- `EnumSet` - оптимизирован для хранения элементов одного перечисления (_enum_), очень быстрый и компактный;
- `CopyOnWriteArraySet` - потокобезопасная реализация на базе `CopyOnWriteArrayList`, используется, если читающих 
  потоков больше, чем записывающих.

Элементы во множестве (`Set`) не имеют индексов, из-за чего для них не доступны методы коллекций, имеющие индексы 
элементов в своей сигнатуре.

#### 2.4.2.1 Хеш-таблица (HashSet)

> [[_оглавление_]](../README.md)

[**HashSet**](/conspect/definitions.md/#h) - это реализация множества (`Set`), основанная на хеш-таблице, которая не 
допускает хранение дубликатов, не сохраняет порядок добавления элементов, допускает хранение элемента 
$\textrm{\color{orange}null}$ и обеспечивает быстрые операции добавления, удаления и поиска за константное время 
(O<sub>(1)</sub>).  

`HashSet` отличается высокой скоростью поиска элементов во множестве.  
В `HashSet` используется механизм хеширования для быстрого поиска, добавления и удаления элементов.  

В основе `HashSet` лежит `HashMap`. Каждый элемент множества хранится в качестве ключа внутри объекта `HashMap`, а его 
значение всегда фиксированное - это специальный объект-заглушка. Этот объект используется для обозначения присутствия 
элемента, так как `HashMap` требует наличие пары "ключ-значение".

Когда элемент добавляется в `HashSet`, для него вычисляется хеш-код с помощью метода `hashCode()`. Этот хеш-код помогает 
определить, в какую "корзину" (_bucket_) поместится элемент. Если два элемента имеют одинаковый хеш-код (коллизия), они 
будут помещены в один и тот же _bucket_, и далее будут различаться с помощью метода `equals()`.

До _Java 8_, если в корзину попадало несколько элементов (коллизия), они сохранялись в виде односвязного списка. Это 
приводило к тому, что в худшем случае производительность поиска и добавления элементов могла падать до O<sub>(n)</sub>, 
если список становился слишком длинным.

С _Java 8_ при превышении `8` элементов в одной корзине, односвязный список преобразуется в красно-чёрное дерево, что 
улучшает производительность операций до O<sub>(log n)</sub>. Когда количество элементов в корзине падает ниже `6`, 
структура снова преобразуется обратно в связанный список для экономии памяти.

В среднем: добавление элемента в `HashSet` занимает константное время (O<sub>(1)</sub>), потому что благодаря хеш-кодам 
можно быстро находить нужную корзину для элемента.  
В худшем случае добавление элемента может занять O<sub>(n)</sub> до _Java 8_ (связный список) и O<sub>(log n) начиная с 
_Java 8_ (красно-чёрное дерево).

Удаление элементов из `HashSet` происходит также через хеш-код: ищется соответствующая корзина, а затем элемент 
удаляется, если он там есть. Сложность удаления аналогична добавлению: O<sub>(1)</sub> в среднем и O<sub>(n)</sub> или 
O<sub>(log n) в худшем случае (в зависимости от структуры корзины).

Преимущества использования _HashSet_: 

- быстрое добавление, удаление и поиск элементов в среднем за O<sub>(1)</sub>, так как используется хеширование;
- улучшенная производительность с _Java 8_ благодаря использованию красно-чёрного дерева.

Недостаток использования _HashSet_ - не гарантирует порядок элементов, а при частых коллизиях, особенно в старых версиях 
_Java_, производительность может падать до O<sub>(n)</sub>.

> Если в классе не реализованы методы `equals()` и `hashCode()`, то _HashSet_ не сможет выбрать корректную ячейку для
> элемента и найти его дубликаты, и в результате `Set` будет представлять из себя просто список элементов, не содержащих
> индексы.

##### 2.4.2.1.1 Связанная хеш-таблица (LinkedHashSet)

> [[_оглавление_]](../README.md)

[**LinkedHashSet**](/conspect/definitions.md/#l) - это реализация множества (`Set`), обеспечивающая хранение уникальных 
элементов с сохранением порядка их вставки. 

`LinkedHashSet`, как и `HashSet`, работает с элементами за константное O<sub>(1)</sub> время, но, в отличие от 
`HashSet`, сохраняет порядок добавления элементов благодаря дополнительной структуре связного списка.

`LinkedHashSet` базируется на `HashMap`, но имеет уникальную особенность - упорядочивание элементов за счёт 
использования связного списка поверх стандартной хеш-таблицы.

`LinkedHashSet` использует `LinkedHashMap` для хранения элементов. Каждый добавляемый элемент выступает в роли ключа, а 
значение всегда фиксировано (обычно это объект-заглушка).

Для поддержания порядка добавления, элементы связаны друг с другом в виде двусвязного списка. Это позволяет итерациям 
проходить элементы в порядке их вставки.

Как и в `HashSet`, каждый элемент уникален. При попытке добавить дублирующий элемент он игнорируется, сохраняя 
уникальность всех значений.

Добавление элементов происходит за амортизированное O<sub>(1)</sub> время. `LinkedHashSet` вычисляет хэш элемента и 
индекс, где он будет храниться в массиве корзин `LinkedHashMap`.  
Удаление происходит также за амортизированное O<sub>(1)</sub> время. `LinkedHashSet` находит элемент по хэшу, удаляет 
его из связного списка и освобождает место в корзине.  
Поиск происходит за амортизированное O<sub>(1)</sub> время благодаря хэш-таблице.

`LinkedHashSet` требует немного больше памяти по сравнению с `HashSet`, так как хранит не только хэш-таблицу, но и 
двусвязный список, поддерживающий порядок добавления элементов. Это делает `LinkedHashSet` более затратным в плане 
памяти, особенно при большом количестве элементов.

Преимущества использования _LinkedHashSet_:

- сохранение порядка добавления элементов;
- быстрая работа с элементами за константное O<sub>(1)</sub> время, как и в `HashSet`.

Недостаток использования _LinkedHashSet_ - потребление ресурсов возрастает при большом количестве элементов, так как 
структура требует больше памяти для поддержания порядка.

#### 2.4.2.3 Сортированное множество (SortedSet)

> [[_оглавление_]](../README.md)

[**SortedSet**](/conspect/definitions.md/#s) - это интерфейс в _Java Collection Framework_, который предоставляет 
упорядочивание элементов во множестве. 

Элементы упорядочиваются с помощью их естественного порядка или с помощью компаратора, который обычно предоставляется 
при создании отсортированного множества.

`SortedSet` имеет несколько дополнительных операций, которые позволяют использовать упорядочение элементов.

##### 2.4.2.3.1 first()

> [[_оглавление_]](../README.md)

Метод `first()` интерфейса `SortedSet` возвращает первый (наименьший) элемент, содержащийся во множестве:

$\textrm{\color{orange}[тип элемента] \color{magenta}[имя переменной] \color{white}= sortedSet.first()}$

Пример:

```java
public static void main(String[] args) {
    SortedSet<String> sortedSet = new TreeSet<>(Comparator.reverseOrder());
    sortedSet.add("A");
    sortedSet.add("D");
    sortedSet.add("C");
    sortedSet.add("B");
    System.out.println(sortedSet);
    String first = sortedSet.first();
    System.out.println(first);
}
```

Вывод:

```text
[D, C, B, A]
D
```

В случае, если искомого элемента нет во множестве, метод выбрасывает исключение _NoSuchElementException_.

##### 2.4.2.3.2 last()

> [[_оглавление_]](../README.md)

Метод `last()` интерфейса `SortedSet` возвращает последний (наибольший) элемент, содержащийся во множестве:

$\textrm{\color{orange}[тип элемента] \color{magenta}[имя переменной] \color{white}= sortedSet.last()}$

Пример:

```java
public static void main(String[] args) {
    SortedSet<String> sortedSet = new TreeSet<>(Comparator.naturalOrder());
    sortedSet.add("A");
    sortedSet.add("D");
    sortedSet.add("C");
    sortedSet.add("B");
    System.out.println(sortedSet);
    String last = sortedSet.last();
    System.out.println(last);
}
```

Вывод:

```text
[A, B, C, D]
D
```

В случае, если искомого элемента нет во множестве, метод выбрасывает исключение _NoSuchElementException_.

##### 2.4.2.3.3 headSet()

> [[_оглавление_]](../README.md)

Метод `headSet()` интерфейса `SortedSet` возвращает множество элементов, которые строго меньше указанного элемента:

$\textrm{\color{white}Set<\color{orange}[тип элементов]\color{white}> \color{magenta}[имя переменной] 
\color{white}= sortedSet.headSet(\color{green}[значение элемента]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    SortedSet<String> sortedSet = new TreeSet<>(Comparator.naturalOrder());
    sortedSet.add("A");
    sortedSet.add("D");
    sortedSet.add("C");
    sortedSet.add("B");
    sortedSet.add("F");
    System.out.println(sortedSet);
    SortedSet<String> sortedSet1 = sortedSet.headSet("C");
    System.out.println(sortedSet1);
    SortedSet<String> sortedSet2 = sortedSet.headSet("E");
    System.out.println(sortedSet2);
}
```

Вывод:

```text
[A, B, C, D, F]
[A, B]
[A, B, C, D]
```

В случае, если элемент несовместим с компаратором, то метод выбрасывает исключение _ClassCastException_.  
В случае, если элемент равен $\textrm{\color{orange}null}$ и множество не поддерживает содержание нулевых элементов, то 
метод выбрасывает исключение _NullPointerException_.  
В случае, если элемент выходит за пределы допустимого для данного множества диапазона, то метод выбрасывает исключение 
_IllegalArgumentException_.

##### 2.4.2.3.4 tailSet()

> [[_оглавление_]](../README.md)

Метод `tailSet()` интерфейса `SortedSet` возвращает множество элементов, которые больше либо равны указанному элементу:

$\textrm{\color{white}Set<\color{orange}[тип элементов]\color{white}> \color{magenta}[имя переменной]
\color{white}= sortedSet.tailSet(\color{green}[значение элемента]\color{white})}$

Пример:

```java
public static void main(String[] args) {
    SortedSet<String> sortedSet = new TreeSet<>(Comparator.naturalOrder());
    sortedSet.add("A");
    sortedSet.add("D");
    sortedSet.add("C");
    sortedSet.add("B");
    sortedSet.add("F");
    System.out.println(sortedSet);
    SortedSet<String> sortedSet1 = sortedSet.tailSet("C");
    System.out.println(sortedSet1);
    SortedSet<String> sortedSet2 = sortedSet.tailSet("E");
    System.out.println(sortedSet2);
}
```

Вывод:

```text
[A, B, C, D, F]
[C, D, F]
[F]
```

В случае, если элемент несовместим с компаратором, то метод выбрасывает исключение _ClassCastException_.  
В случае, если элемент равен $\textrm{\color{orange}null}$ и множество не поддерживает содержание нулевых элементов, то
метод выбрасывает исключение _NullPointerException_.  
В случае, если элемент выходит за пределы допустимого для данного множества диапазона, то метод выбрасывает исключение
_IllegalArgumentException_.

##### 2.4.2.3.5 subSet()

> [[_оглавление_]](../README.md)

включительно и меньше второго указанного элемента не включительно:

$\textrm{\color{white}Set<\color{orange}[тип элементов]\color{white}> \color{magenta}[имя переменной]
\color{white}= sortedSet.subSet(\color{green}[значение элемента "ОТ"]\color{white}, 
\color{green}[значение элемента "ДО"]\color{white})}$

Пример:


В случае, если один из передаваемых элементов равен $\textrm{\color{orange}null}$ и множество не поддерживает содержание 
нулевых элементов, то метод выбрасывает исключение _NullPointerException_.  
В случае, если один из передаваемых элементов выходит за пределы допустимого для данного множества диапазона или элемент 
"ОТ" больше элемента "ДО", то метод выбрасывает исключение _IllegalArgumentException_.

### 2.4.4 Очередь (Queue)

> [[_оглавление_]](../README.md)

[**Очередь (Queue)**](/conspect/definitions.md/#q) - это структура данных, представляющая из себя упорядоченный набор
элементов, в которой добавление новых элементов производится в конец, называемый **хвостом очереди**, а удаление
существующих производится с другого конца, называемого **головой очереди**.  
Очереди в Java работают по двум принципам: _FIFO_ и _LIFO_.

[**LIFO (last-in, first-out)**](/conspect/definitions.md/#l) - это принцип, при котором первым удаляется элемент,
который был помещен туда последним («последним вошел — первым вышел»).

![1.jpeg](/pictures/1.jpeg)

В очереди реализован принцип _FIFO_.  
[**FIFO (first-in, first-out)**](/conspect/definitions.md/#f) - это принцип, при котором первым удаляется элемент,
который был помещен туда первым («первым вошел — первым вышел»).

![2.png](/pictures/2.png)

В Java структура данных очередь представлена не классом, а интерфейсом - `Queue`.  
Но вместе с тем, очередь в Java - это интерфейс, у которого есть очень много реализаций. Самым распространённым из
используемых субинтерфейсов, реализующих интерфейс `Queue`, является интерфейс `Deque` (двусторонняя очередь).  
Двусторонняя очередь `Deque` расширяет функционал обычной очереди, позволяя добавлять элементы на оба края (в начало и
конец очереди) и забирать элементы с обоих краев очереди.

![3.png](/pictures/3.png)

У _Queue_ есть три класса реализации: _LinkedList_, _ArrayDeque_ (наследуемые от _Deque_) и _PriorityQueue_ (наследуемая
напрямую).

> Очередь (_Queue_) как и множество (_Set_) не имеет методов `get()` и `set()`.

Класс _ArrayDeque_ поддерживает двустороннюю структуру данных очереди, что дает возможность вставлять и удалять элементы
с обеих сторон. Также он - динамический массив, который может автоматически увеличивать свой размер.

Класс _PriorityQueue_ - это очередь с приоритетом, которая по умолчанию размещает элементы согласно естественному
порядку сортировки. Для сортировки здесь используется _Comparable_ и _Comparator_.

Например:

```java
private static void dequeExample() {
    PriorityQueue<String> priorityQueue = new PriorityQueue<>(Comparator.comparingInt(String::length));
    priorityQueue.add("John");
    priorityQueue.add("Andrew");
    priorityQueue.add("Rob");
    while (!priorityQueue.isEmpty()) {
        System.out.println(priorityQueue.remove());
    }
}
```

После запуска в консоли будет выведено:

```text
Rob
John
Andrew
```

### 2.4.5 Мап (Map)

> [[_оглавление_]](../README.md)

[**Map (Мап)**](/conspect/definitions.md/#m) - это структура хранения данных в формате «ключ-значение».  
Мапы являются [ассоциативными массивами](/conspect/definitions.md/#а).

_Map_ не реализует интерфейсы `Iterable` и `Collection`, поэтому у него нет общих для коллекций методов, только свои.  
У интерфейса _Map_ есть ряд реализаций: `TreeMap`, `HashMap`, `LinkedHashMap` и др.

Значения в _Map_ могут повторяться, а ключи - нет.

`HashMap` и `LinkedHashMap` позволяют использовать `null` в качестве одного из ключей, а `SortedMap` (и его
потомок `TreeMap`, соответственно) - нет.

> Итерироваться по мапам с помощью циклов нельзя!

#### 2.4.5.1 HashMap

> [[_оглавление_]](../README.md)

[**HashMap**](/conspect/definitions.md/#h) - это Map, в которой пара «ключ-значение» добавляется в хранилище по
уникальному числовому коду объекта - хеш-коду ключа.

Ключами в _HashMap_ должны быть неизменяемые объекты. Если изменить объект, то изменится и _hashCode_, а значит, быстро
найти этот элемент в коллекции по первоначальному хеш-коду станет невозможно. Поэтому обычно в качестве ключей
используются строки или числа.

Данные в _HashMap_ хранятся в корзинах (_buckets_), в каждой из которых находятся от 1 до 8 узлов (_Node_), собранных в
связный список, или (при количестве _Node_ большем 8) самобалансирующееся бинарное дерево, помогающее ускорить поиск
внутри корзины. Каждый узел содержит ключ, значение, хеш-код (высчитываемый сложением хеш-кода ключа и хеш-кода
значения) и ссылку на соседний узел.

```java
static class Node<K, V> implements Map.Entry<K, V> {
    final int hash;
    final K key;
    V value;
    Node<K, V> next;
    // ...
}
```

[**Бинарное дерево**](/conspect/definitions.md/#б) - это дерево, в котором для любого узла выполняется правило: потомки
слева этого узла всегда меньше него, потомки справа - всегда больше.

У _HashMap_ есть метрика `loadFactor`, определяющая процент загрузки пространства корзин, после которого происходит
автоматическое расширение пространства в памяти (по умолчанию равна `0.75f`).  
Расширение происходит путём увеличения количества корзин в 2 раза, пересчёта хешей для всех узлов и их перераспределения
по корзинам с учётом нового их количества.

> В _HashMap_ порядок хранения пар «ключ-значение» не гарантируется: пары хранятся в соответствии с хеш-кодами, а не
> ключами или значениями.

> [[_оглавление_]](../README.md)

Метод `values()` класса `HashMap` применяется для создания из всех значений мапы коллекции.  
Синтаксис метода выглядит следующим образом:

```text
Collection<[тип значения]> keySet = map.values();
```

Данный метод возвращает коллекцию, состоящую из содержащихся в мапе значений.

##### 2.4.5.1.11 entrySet()

> [[_оглавление_]](../README.md)

Метод `entrySet()` класса `HashMap` применяется для создания множества (_Set_) из содержащихся в мапе пар
"ключ-значение".  
Синтаксис метода выглядит следующим образом:

```text
Set<Entry<[тип ключа], [тип значения]>> entrySet = map.values();
```

Данный метод возвращает множество (_Set_), состоящее из содержащихся в мапе пар "ключ-значение".  
Получаемое таким образом множество позволяет итерироваться по мапе, а также сохраняет взаимосвязь с содержащимися в мапе
элементами, за счёт чего в случае внесения изменений в элементы получаемого множества (_Set_) эти изменения также будут
внесены в мапу, на основании которой это множество создано.

#### 2.4.5.2 LinkedHashMap

> [[_оглавление_]](../README.md)

[**LinkedHashMap**](/conspect/definitions.md/#l) - это реализация интерфейса `Map`, содержащая пары "ключ-значение" в
порядке их добавления.

Класс `LinkedHashMap` поддерживает двусвязный список, проходящий через все его записи.  
Если `HashMap` - это, по сути, массив с 16 ячейками, то `LinkedHashMap` еще и связывает все эти ячейки. Чтобы сохранить
порядок элементов, `LinkedHashMap` изменяет класс `Map.Entry`, добавляя указатели на следующую и предыдущую записи.

#### 2.4.5.3 TreeMap

> [[_оглавление_]](../README.md)

[**TreeMap**](/conspect/definitions.md/#t) - это реализация интерфейса `Map`, которая сортирует пары "ключ-значение" в
соответствии с естественным порядком ключей или по компаратору, если он предоставляется разработчиком во время создания
реализации.

По умолчанию _TreeMap_ сортирует все свои записи в соответствии с их естественным порядком. Для целых чисел естественный
порядок - это возрастающий (от меньшего к большему), для строк - алфавитный.

_TreeMap_ не использует хеширование, так как вместо массива в нём - структура дерева для хранения и сортировки
элементов.  
В _TreeMap_ можно использовать свои классы в качестве ключей, но для этого нужно реализовать в них
интерфейс `Comparable` или при создании указать компаратор.

#### 2.4.5.5 Интерфейс Map.Entry

> [[_оглавление_]](../README.md)

Интерфейс _Map.Entry_ в Java позволяет работать с записями _Map_.

> Интерфейс _Map_ не реализует интерфейс _Iterable_, по этой причине итерироваться по элементам `Map` напрямую нельзя.

Метод `entrySet()`, объявленный интерфейсом _Map_, возвращает `Set`, содержащий записи `Map`. Каждый из этих элементов
является объектом `Map.Entry`.  
Каждый из объектов `Map.Entry` сохраняет связь со своей базовой `Map`, поэтому изменения в нём будут также внесены в
аналогичный элемент базовой `Map`.

Пример:

- создадим `Map`, внесём в неё значения, а затем преобразуем при помощи `Map.Entry` так, чтобы она содержала только
  нечётные числа:

```java
private static void mapEntryExample() {
    Map<String, Integer> map = new HashMap<>();
    map.put("key 1", 1);
    map.put("key 2", 2);
    map.put("key 3", 3);
    Set<Map.Entry<String, Integer>> entrySet = map.entrySet();
    System.out.println(entrySet);
    System.out.println(map);
    for (Map.Entry<String, Integer> entry : entrySet) {
        if (entry.getValue() % 2 == 0) {
            entry.setValue(entry.getValue() + 1);
        }
    }
    System.out.println();
    System.out.println(entrySet);
    System.out.println(map);
}
```

- в терминале получим:

```text
[key 3=3, key 2=2, key 1=1]
{key 3=3, key 2=2, key 1=1}

[key 3=3, key 2=3, key 1=1]
{key 3=3, key 2=3, key 1=1}
```

### 2.4.1 Класс Collections

> [[_оглавление_]](../README.md)

Класс _Collections_ представляет собой аналог класса _Arrays_ в отношении массивов. В нём собраны различные статические
